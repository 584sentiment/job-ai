### 🔴 Critical (严重级别)

#### 问题1: 用户统计接口数据库错误
- **发现时间**: 2026-01-31
- **模块**: 用户体系模块
- **接口**: `GET /api/users/stats`
- **问题描述**: 调用用户统计接口时返回500错误，提示"数据库操作失败"
- **复现步骤**:
  1. 用户登录后访问个人中心页面
  2. 前端调用 `GET /api/users/stats` 接口
  3. 后端返回500错误
- **错误信息**: `{"code": 500, "message": "数据库操作失败"}`
- **影响范围**: 个人中心页面无法展示用户统计数据（岗位数量、面试数量等）
- **根因分析**: 数据库查询语句可能存在问题，或数据库表结构不匹配
- **建议修复方案**:
  1. 检查后端 `src/controllers/user.controller.ts` 中的 `getUserStats` 方法
  2. 验证数据库查询语句是否正确
  3. 确认数据库表结构和字段是否存在
- **状态**: 🔄 待修复
- **优先级**: P0 (立即修复)

### 🟡 High (高优先级)

#### 问题2: AI对话功能仅为占位响应
- **发现时间**: 2026-01-31
- **模块**: AI功能模块
- **接口**: `POST /api/ai/chat`
- **问题描述**: AI助手对话功能返回固定的占位消息，未接入真实AI服务
- **复现步骤**:
  1. 访问AI助手页面
  2. 发送任意消息
  3. 收到固定响应："抱歉，AI助手暂时无法响应。请稍后再试。"
- **影响范围**: AI助手核心功能不可用，用户体验受损
- **根因分析**: AI功能尚未接入真实API（如DeepSeek、OpenAI等）
- **建议修复方案**:
  1. 在 `src/services/ai.service.ts` 中接入真实AI API
  2. 配置API密钥和请求参数
  3. 添加错误处理和降级方案
- **状态**: 🔄 待修复
- **优先级**: P1 (本周完成)

#### 问题3: 岗位准备清单参数格式不一致
- **发现时间**: 2026-01-31
- **模块**: 面试管理模块
- **接口**: `POST /api/ai/generate-prep-list`
- **问题描述**: 接口期望接收 `interview` 对象，但前端可能传递其他格式的数据
- **影响范围**: 面试准备清单生成功能可能出现参数错误
- **建议修复方案**:
  1. 统一前后端参数格式
  2. 在后端添加参数验证和类型转换
  3. 提供更灵活的参数支持（支持直接传岗位ID）
- **状态**: 🔄 待修复
- **优先级**: P1 (本周完成)

### 🟢 Medium (中优先级)

#### 问题4: 日期参数格式不统一
- **发现时间**: 2026-01-31
- **模块**: 岗位管理、面试管理模块
- **问题描述**: 部分接口需要时间戳（BigInt），部分接口接受日期字符串，格式不统一
- **影响范围**: 可能导致前端调用API时参数格式错误
- **建议修复方案**:
  1. 统一使用时间戳（推荐）或统一使用ISO日期字符串
  2. 在API文档中明确说明参数格式
  3. 在前端工具函数中统一处理日期转换
- **状态**: 🔄 待修复
- **优先级**: P1 (本周完成)

#### 问题5: Tags参数类型不一致
- **发现时间**: 2026-01-31
- **模块**: 面经管理模块
- **接口**: `POST /api/experiences`
- **问题描述**: 创建面经时 `tags` 参数必须是数组，但用户可能输入字符串
- **影响范围**: 用户输入标签时可能出现格式错误
- **建议修复方案**:
  1. 前端添加字符串到数组的自动转换
  2. 后端添加参数验证和格式转换（支持字符串和数组）
  3. 提供用户友好的标签输入方式（如标签选择器）
- **状态**: 🔄 待修复
- **优先级**: P1 (本周完成)

#### 问题6: 用户统计功能缺失
- **发现时间**: 2026-01-31
- **模块**: 用户体系模块
- **问题描述**: 无法获取用户的岗位数量、面试数量、面经数量等统计数据
- **影响范围**: 个人中心无法展示数据统计卡片
- **建议修复方案**:
  1. 实现统计查询逻辑
  2. 使用数据库聚合查询（COUNT、GROUP BY等）
  3. 添加缓存机制提升性能
- **状态**: 🔄 待修复
- **优先级**: P1 (本周完成)

### 🔵 Low (低优先级)

#### 问题7: 搜索功能可能存在性能问题
- **发现时间**: 2026-01-31
- **模块**: 面经管理模块
- **接口**: `POST /api/experiences/search`
- **问题描述**: 未验证大量数据时的搜索性能，可能出现查询缓慢
- **影响范围**: 面经数量较多时搜索响应变慢
- **建议修复方案**:
  1. 为搜索字段添加数据库索引
  2. 考虑使用全文搜索引擎（如Elasticsearch）
  3. 添加搜索结果缓存
- **状态**: 📋 待观察
- **优先级**: P3 (后续优化)
